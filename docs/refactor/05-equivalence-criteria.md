## 티어 정의

| 티어 | 의미 | 비교 방법 |
|---|---|---|
| **T1 — 완전 일치** | 값이 비트/문자열/정수 단위로 같아야 함 | 직렬화 결과 문자열 diff, 오차 0 |
| **T2 — 허용 오차 내** | 수치 오차 한계 내면 통과 | 절대오차 비교. 한계값은 §T2 참조 |
| **T3 — 달라도 정상** | 플랫폼 래스터라이저·폰트·프레임 타이밍 차이. 동등성 대상 아님 | 비교하지 않음. 단 T3 뒤에 숨은 T1 정책이 없는지 1단계에서 확인 |

## T2 허용 한계값과 근거

| 비교 대상 | 한계 | 근거 |
|---|---|---|
| 코어 산출 Double을 JVM ↔ iosNative에서 비교 | **절대오차 1e-9** | 코어는 100% commonMain 단일 구현(00-baseline §3)이므로 원칙적으로 비트 동일이 기대치다. 남는 차이 원인은 Kotlin/JVM vs Kotlin/Native의 수학 함수(`log10`, `pow` — `scale/NiceScale.kt:53-55`에서 사용) 구현 차이뿐이며, 이는 최종 자리 ULP 수준이다. 정규화 좌표(0~1) 기준 1e-9는 3000px 화면에서 3e-6px — 시각적으로 0. 이보다 큰 차이는 "부동소수 잡음"이 아니라 구현 결함으로 취급한다 |
| 렌더러 자체 구현 값(코어 미경유)을 iOS ↔ AOS에서 비교 | **절대오차 1e-6** | iOS는 `CGFloat`(64bit), Compose는 `Float`(32bit)를 쓰는 지점이 있다(예: AOS `ChartStyle.kt` `val lineWidth: Float` vs iOS `ChartStyle.swift:6` `var lineWidth: CGFloat`). Float의 0~1 구간 표현 오차 상한 ~6e-8에 연산 누적 여유를 곱해 1e-6. 3000px 화면 기준 0.003px — 시각적으로 0 |
| 시간·거리 등 도메인 값(초, m) | 위와 동일 비율 — 값 크기 × 1e-9 (상대오차) | 절대오차는 0~1 정규화 전제라 큰 도메인 값(예: 러닝 10000초)에는 상대오차로 환산 적용 |

주의: 오차 비교는 **고정 자릿수 직렬화(0.7단계) 이후 파싱한 값**으로 한다. 플랫폼 `toString` 차이를 값 차이로 오인하지 않기 위함이다.

### 공통 — T3 목록 (동등성 비교 제외)

- 안티에일리어싱, 서브픽셀 배치, 래스터화 결과 픽셀
- 글리프 어드밴스·폰트 메트릭 **실측값**, 폰트 폴백
- 프레임 타이밍, 디스플레이 리프레시 동기화
- 스크롤/제스처의 OS 기본 물리(관성 곡선)

### T3 위장 경계 (명시 요구사항)

T3처럼 보이지만 T1인 것 — 1단계 대조 시 반드시 이 렌즈로 재검:

1. **라벨 솎아내기**: 텍스트 폭 실측은 T3지만, "어떤 라벨을 버릴지" 결정 규칙은 T1.
   코어에 `query/LabelThinning.kt`가 이미 존재한다 — 렌더러가 각자 솎아내면
   T1 정책이 네이티브로 샌 것(그림자 또는 비대칭). 1단계에서 판정.
2. **텍스트 폭에 따른 레이아웃 보정**(라벨 겹침 회피, 축 라벨 영역 폭): 측정은 T3,
   측정값을 받아 내리는 배치 결정은 T1.
3. **밀도 환산**: dp/pt 논리값과 환산식은 T1. 환산 후 정수 픽셀 스냅만 T3.
